# Changelog

All notable changes to this project are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- `scaffold --dry-run` (MCP `dry_run=True`): the plan, the field inventory and the Notes, with
  nothing written. The inventory lists every leaf of the sample with its outcome — an entity, a
  property, or dropped with a reason.
- `scaffold --records PATH` and repeatable `--map PATH=TYPE` (`TYPE` is an entity class,
  `Property` or `Drop`) to choose the records and override single fields. A `--map` works on a
  field empty in the sample or inside a metadata or envelope subtree, is exempt from depth limits
  and the 30-property cap, and is marked `(--map)` in the inventory; one that cannot be honoured
  is an error. `Property` inside a nested list with no entity goes on the enclosing record's
  primary, values joined with `, `.
- `scaffold --primary PATH` (MCP `primary`), written like a `--map` path: the field that is each
  record's primary entity. It must be a single-valued entity field, inferred or made one by
  `--map`; the error otherwise lists the candidates.
- `scaffold --sample-input VALUE` (MCP `sample_input`): the input the sample response answers,
  recorded in `samples.json` and used to recognise the input echoed back. cURL defaults to the
  request's value; OpenAPI to the input parameter's `default`, `enum`, `example`, `x-example` or
  `examples`, with a Note when there is none.
- `scaffold --name` for cURL scaffolds, so one service grows endpoint by endpoint. A new endpoint
  joins an existing service only when the regenerated `api.py` would be byte-identical.
- `scaffold --list-operations` and the MCP tool `list_operations`: each OpenAPI operation's method,
  path, transform id, input, response schema and skip reason. An operationId the spec reuses is
  marked `*`, with a footer on picking one by its TRANSFORM value.
- `remove-scaffold SERVICE` and the MCP tool `remove_scaffold`: deletes a scaffolded service
  directory and its `project.py` imports. A service whose `api.py` lacks the line
  `Generated by transformatron scaffold.` (hand-written, like the bundled samples) is refused.
- `transforms/<service>/samples.json`, written by `scaffold`, mapping each transform id to its
  sample input. The smoke test reads it first.
- Scaffold output names each transform by its registered id (`<namespace>.<service>_<name>`) and
  prints a ready-to-paste `run` command per transform (`VALUE` when there is no sample input).
- `run`/`show` with an id the server does not know add a hint to the 404: `list`, the
  `<namespace>.<id>` form when the id has no dot, and a restart for a transform added since start.
- A run in a success state with zero entities and an `[ERROR]` message prints a `Warning:` line
  under the state. The exit code is unchanged.
- OpenAPI specs in YAML; `--sample-response` with exactly one `--operation`.
- `run --json` (MCP `full=True`) for the full JSON of every entity and link.
- A `stop` or `restart` that has to kill the server names the cause from the server log: a
  transform blocking the runner thread, open client connections, a pending TLS handshake.
- `server/project.py` bounds uvicorn's graceful shutdown to 3s, so an HTTPS stop with Maltego
  Desktop connected takes about 3.4s instead of a 10s kill. `docs/upstream-sdk-shutdown-issue.md`
  is the upstream draft.
- Smoke test defaults for `maltego.CVE` and `maltego.Hash`; exhausted credits (402) and the
  scaffolder's "has no record for the requested input" report SKIP.
- Dependabot for uv and GitHub Actions.
- `docs/transform-authoring.md`: Correction 3 (`add_property` does not exist), never block in a
  transform, reading a run, and editing `RECORDS`.

### Changed

- Upgraded to `maltego-transforms` 1.3.0, `maltego-transforms-std-entities` 1.0.2, `mcp` 2.3.0
  and `httpx` 0.28.1. 1.3.0 fixes entity updates lost between result polls and boolean settings
  sent as `"false"` being read as true. mcp 2.1 and later keep a crashing tool's error text on
  the server, so MCP tools now raise `ToolError` with `<ExceptionType>: <message>` for the agent.
- The scaffolder maps one primary entity per record, with the record's plain values as properties
  and its other typed values as linked entities, instead of one entity per field. Fields are
  addressed by path: typed values 4 levels into a record, properties 3. Envelope and metadata
  keys are dropped and reported. Each module holds a `RECORDS` table walked by `map_records` in
  `api.py`; multi-line values are split and the input's own value skipped. An entity met in
  several records is returned once, carrying every record's property values, distinct values
  joined with `, `.
- Records are found behind up to two wrapper objects, past summary keys (`_shards`,
  `aggregations`, `aggs`, `facets`) and, inside a wrapper, float, boolean or null siblings, so
  Elasticsearch `hits.hits` is detected. A top-level record with no single-valued typed field
  becomes a `Phrase` titled by `name`, `title`, `label`, `displayname`, `fullname`, `summary`,
  `id` or `identifier`; a title needs 4 characters or more and is never an `ENUM_CASE` value,
  `true`/`false`/`null`/`none`/`n/a`, or a number outside `id`/`identifier`.
- When the whole response is one record, a top-level envelope key (`status`, `version`, `total`,
  …) is dropped only when another envelope key sits beside it; alone it is a field of the record.
- cURL scaffolds send every header from the command (except auth and connection headers), plus
  `-A`, `-e` and `-b`, and keep repeated query parameters. Flags they cannot reproduce are noted.
- OpenAPI transform ids are `<service>_<operation>`, with modules named after the operation.
  GETs whose first path-segment word, or first operationId word past a leading
  `get`/`post`/`api`/`do`, is a state-changing verb (`create`, `delete`, `remove`, `update`,
  `edit`, `login`, `logout`, `register`, `reset`, `set`, `add`, `insert`, `upload`, `import`,
  `purge`, `flush`, `revoke`, `subscribe`, `unsubscribe`, `start`, `stop`), and operations whose
  only input is a paging or optional parameter, are skipped unless named. Where the spec allows
  anonymous access the key is sent when set and not required.
- `scaffold --force` replaces the whole service directory and its `project.py` imports, and
  refuses a service the scaffolder did not write. A
  transform id already defined anywhere under `transforms/` is refused before anything is written,
  and the service name `local` is reserved.
- Key-name heuristics match on camel, kebab and snake words, and the value can veto a name match
  (`state: PUBLISHED` is not a Location; a distinguished name is not a Person). Hex digests map to
  `Hash`.
- `run` output is compact: `Entities (N, M distinct):`, one line per entity with its non-blank
  properties and link label, each message prefixed by its level (`[INFO]`, `[WARNING]`,
  `[ERROR]`, `[DEBUG]`), and on `FAILED` the traceback the server logged during the run.
- Long generated display names are cut at a word, and long property labels cut, ending in `…`
  instead of `...`.
- The smoke test fails a zero-entity run with its `[ERROR]` message, and shows the `MaltegoGraph`
  hint only when a run produced no messages.
- `server/README.md` points at the root README instead of describing the SDK starter.

### Fixed

- MCP `scaffold_transform` accepts `sample_response` and `openapi` as JSON text; mcp's argument
  pre-parsing had turned them into objects and rejected them.
- A run polled between the SDK marking it `FAILED` and logging the crash returned no message.
- OpenAPI: a Swagger 2 spec with `basePath` and no `host` lost the base path; it is now resolved
  against the spec's URL, with the spec URL's scheme when the spec names none.
- OpenAPI: operations sharing an operationId were written as identical transforms, and the
  printed ids differed from the registered ones. Each now gets a distinct id from the path words
  or parameters the others lack (numbered as a last resort) and a display-name qualifier such as
  `(by number)`.
- A schema-built sample (no values) typed `name`, `owner`, `contact`, `state`, `region` and
  `province` fields by key alone, so a Petstore pet's tag `name` became a `Person`.
- Generated key messages doubled "API" for a service whose title ends in it
  (`Vulnerability-Lookup API API Key`).
- A non-JSON `--sample-response` now says CSV and plain text are unsupported and how to write
  the parsing by hand.
- Docs: a bare `-> list` stops the server starting (it does not register with output `NONE`), and
  the scaffolder no longer claims to map every field.

### Removed

- The 'every field is mapped' scaffold output and the one-level-deep nesting limit.

## [0.1.0] - 2026-09-28

Everything on `main` up to `06abe61`, tagged `v0.1.0`.

### Added

- MCP control plane for a local Maltego v3 transform server: start, stop, restart, status, logs,
  list transforms and entities, run a transform to completion, seed URL, self-signed HTTPS
  certificates.
- A CLI over the same `transformatron.operations` module, with exit code 1 on failure.
- `scaffold` from a cURL command or an OpenAPI spec: input detection from path, query or body,
  POST bodies, auth as a `TransformSetting`, `$ref` resolution, specs by URL, POST operations only
  when named, `EntityTypeConstraint` inputs, and generated code that passes the project's lint
  gates.
- `scripts/smoke_test_transforms.py`: runs every transform and fails on zero entities or an output
  type of `NONE`, with `--setting` and SKIP for a missing credential, a rate limit, a rejected
  sample, or no upstream match.
- `.env` for headless credentials, read by the server and the smoke test.
- `transformatron.toml` for server name, namespace, author, host and port.
- `server/transforms/local/`, gitignored and discovered at startup, for packages and single-file
  modules.
- Sample transforms: ffraud, RDAP, ransomware.live, IPinfo Lite, CrowdSec CTI and GreyNoise, and
  the SDK's transform middleware pattern.
- `AGENTS.md`, `CLAUDE.md`, the `maltego-transform-author` skill, `docs/transform-authoring.md`
  and the draft upstream report `docs/upstream-sdk-issue.md`.
- CI on Ubuntu and macOS with Python 3.13 and 3.14, and a daily live smoke test.

### Fixed

- Runs larger than one page of events were truncated at 25 entities.
- `restart` downgraded an HTTPS server to HTTP; the scheme is now recorded and preserved.
- The generated certificate lacked `digitalSignature`, so TLS 1.3 clients rejected it.
- Stops always fell through to SIGKILL because the child was never reaped.
- Scaffolding an existing service overwrote hand-written modules; query-string API keys were
  never sent.
